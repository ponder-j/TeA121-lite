## 1. 样例一 `test.c`：一次性常量越界（definite）

```c
int main() {
    char buffer[10];
    buffer[10] = 'H';   // 越界 1 字节
    return 0;
}
```

MiniIR 里只有 4 条非 terminator 指令：`alloca`、`nop`（dbg.declare）、`gep`、`store`
（见 02 §5 的真实 JSON）。trace 模式的 4 个事件：

| # | 指令 | 转移后状态（变化部分） | 说明 |
|---|---|---|---|
| 0 | `alloca v0` | 登记对象 `main/v0 size=[10,10]`；`v0 = {base:main/v0, off:0}` | 对象 id 与大小诞生 |
| 1 | `nop` | 无变化 | 调试指令被忽略 |
| 2 | `gep v1 = v0, index 10` | `v1 = {base:main/v0, off:[10,10]}` | 全常量 GEP 折叠成 10 字节偏移 |
| 3 | `store v1, 宽1` | 可见字段无变化（内部会写标量摘要 `scalar_memory[(main/v0,10)]=[72,72]`，但 trace JSON 的 `_state_json` 不序列化该字段） | **在这里产生告警** |

第 3 步 `_check_access` 判定（对象大小 [10,10]，偏移 [10,10]，宽 1）：
- `safe`：`offset.upper + width = 10 + 1 = 11 ≤ size.lower = 10`？**否**；
- `definite`：`offset.lower + width = 10 + 1 = 11 > size.upper = 10`？**是** → `definite`。

文本输出：
```text
tea121 succeeded | alarms=1 diagnostics=0
DEFINITE: main <instruction> object=main/v0 offset=[10,10] size=[10,10] width=1 (out_of_bounds)
```

JSON 里这条 alarm 的关键字段（真实）：
```jsonc
{"alarm_key": "main::main/v0", "severity": "definite", "instruction_id": "",
 "memory_object_id": "main/v0",
 "object_size": {"lower": 10, "upper": 10},
 "offset": {"lower": 10, "upper": 10}, "access_size": 1,
 "reason": ["access range is not provably inside the stack object",
            "access width exceeds object bounds"],
 "source_location": {"file": ".../test.c", "line": 3, "column": 16}}
```

## 2. 样例二 `test_loop.c`：循环越界（possible，widen 的代价）

```c
int main() {
    int buffer[10];                 // 40 字节
    for (int i = 0; i <= 10; i++) { // i 会到 10 → buffer[10] 越界
        buffer[i] = i + 1;
    }
    return 0;
}
```

mem2reg 后的 CFG（5 个块）：

```text
bb0 ──► bb1(循环头: phi .0; icmp .0<=10)
          ├─ true ─► bb2(store: v3=sext .0; v4=gep; store) ─► bb3(i++: .0+1) ──► bb1
          └─ false ─► bb4(ret 0)
```

### 2.1 当前 widening/narrowing 结果

worklist 在内部仍按 `widen_after=3` 对循环变量外推；全部块稳定后，solver 会执行 narrowing，
再从最终状态重放指令转移。对 unsafe 循环，最终关键状态是：

| 块 | 入口 `.0` | 出口 `.0` | 说明 |
|---|---|---|---|
| `bb1` 循环头 | Top（状态在 phi 前） | `[0,11]` | phi 合并初值 0 与回边 `i+1` |
| `bb2` true 边/循环体 | `[0,10]` | `[0,10]` | `i <= 10` 的 true 边把上界收紧为 10 |
| `bb4` false 边/退出 | `[11,11]` | `[11,11]` | `i <= 10` 为假时 `i >= 11` |

bb2 中 `sext` 保留 `[0,10]`，GEP 按 `index*4` 得到偏移 `[0,40]`，store 宽度 4：
`offset.upper + 4 = 44 > size.lower = 40`，但 `offset.lower + 4 = 4 <= 40`，所以结论是
**possible**。文本输出（真实运行）：

```text
tea121 succeeded | alarms=1 diagnostics=0
POSSIBLE: main <instruction> object=main/v0 offset=[0,40] size=[40,40] width=4 (out_of_bounds)
```

这里不再退化成 offset=Top：因为单侧无穷算术会保留已知上界，例如 `[None,10] + 1 = [None,11]`、
`[None,10] × 4 = [None,40]`。

### 2.2 trace 的正确读法

solver 把“求状态”和“产生效应”分开：

- worklist 与 narrowing 期间只计算 `entry_states/exit_states`，不追加 Alarm/Diagnostic/Trace；
- 固定点稳定后，才用最终 `entry_states` 重放一次指令，生成 trace、告警和诊断。

因此 `block_states` 与告警使用同一个稳定状态，不会出现“告警是中间 Top、block_states 却更精确”的
旧问题。`--mode trace` 现在表示**最终稳定状态上的逐指令快照**，不是所有 worklist 迭代日志。

> 代价说明：当前 widening 仍发生在任何访问超过阈值的块，而不是先用支配关系精确识别循环头。
> 这不影响本组样例的正确性，但会把部分非循环块也保守加宽；后续可用 CFG backedge/支配树进一步收敛。

## 3. 样例三 `test_loop_br.c`：带 break 的安全循环（0 告警）

```c
int main() {
    int buffer[10];
    for (int i = 0; i <= 10; i++) {
        if (i >= 10) { break; }   // 写到 buffer[i] 前先拦住 i=10
        buffer[i] = i + 1;        // 真实只写 i=0..9 → 确实安全
    }
    return 0;
}
```

真实运行：`tea121 succeeded | alarms=0 diagnostics=0`。

CFG：`bb0→bb1→(bb2: i>=10)→bb3(break) / bb4(store)→bb5(i++)→bb1`。

这个样例中的 break 守卫是 `if (i >= 10) break;`。到达 store 的路径是条件的 **false 边**，
因此 `_refine_cmp` 把它转为 `i < 10`，循环体入口得到 `i ∈ [0,9]`；GEP 偏移最多 36 字节，
store 宽度 4，36+4=40 ≤ 40，于是安全结论由守卫真实证明，而不是依赖旧版的 join 塌缩。

真实运行：`tea121 succeeded | alarms=0 diagnostics=0`。

## 4. 边界实验：guard 后仍可检出越界（loop_guard_oob.c）

```c
extern int external_condition;
int main() {
    int buffer[10];
    for (int i = 0; i <= 100; i++) {
        if (external_condition) { break; }   // 条件不可分析
        buffer[i] = i;                        // external_condition==0 时 i=10..100 全部越界
    }
    return 0;
}
```

真实运行：**`alarms=1`，诊断为 `UNKNOWN_BASE`（外部条件本身无法解析），不再漏报**。

```text
tea121 succeeded | alarms=1 diagnostics=1
POSSIBLE: main <instruction> object=main/v0 offset=[0,400] size=[40,40] width=4 (out_of_bounds)
UNKNOWN_EFFECT: UNKNOWN_BASE pointer base cannot be resolved
```

固定点状态下，循环头上界是 100，store 偏移为 `[0,400]`；4 字节写入在对象 40 字节上产生
possible。外部 guard 不会错误地把循环索引收紧到安全范围，因此漏报被消除。

## 5. 本轮已修复与剩余边界

| # | 旧差距 | 本轮实现 | 可观测结果 |
|---|---|---|---|
| 1 | join 对无穷端点非吸收 | 任一端无穷结果端保持无穷；Top 吸收 | `[0,2] ⊔ [0,+∞) = [0,+∞)` |
| 2 | 分支只精化部分 true 边 | `eq/ne/lt/le/gt/ge` + signed/unsigned；false 边取否定；常量双向传播 | `if (i >= 10) break` 的 false 边得到 `i ≤ 9` |
| 3 | widening 后精度不可恢复 | 全局稳定后执行只减不增的 bounded narrowing | 安全循环 `.0 ∈ [0,9]`，unsafe 循环保留 `[0,10]` |
| 4 | PHI 在合并入口取值 | 每条前驱边保存精化状态，PHI 按 incoming 的 predecessor 取值 | 未到达的回边不再以 Top 污染 phi |
| 5 | 单侧无穷算术直接 Top | add/sub 保留单侧端点；单点因子乘法保留方向与单侧界 | `[None,9]+1=[None,10]`、`[None,9]×4=[None,36]` |
| 6 | 中间轮次告警不回撤 | 状态求解关闭副作用，最终固定点重放 | alarm/trace/block_states 来自同一稳定状态 |

仍保留的边界：

- widening 触发点是“块访问次数”，尚未精确识别支配关系意义上的所有循环头；非循环块也可能被加宽。
- `State.narrow` 是区间/指针分量的 meet，不包含关系域，无法恢复 `x = i + 1` 这类变量间关系。
- 不可解析的 guard 条件仍会产生 `UNKNOWN_BASE` 诊断；告警是否正确取决于其他可证明的界。
